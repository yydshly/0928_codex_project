跟着一个真实模板走六步

模板 list-grid-compact-card 来自 v0.2.20。下方内容和坐标示例用于解释过程；它们是静态教学说明。

  1. 01

    接收内容和模板名称

    输入指定模板名，并填写三条列表内容。语法解析后得到配置与数据。

    infographic list-grid-compact-card
data
  title 我的工作流程
  lists
    - label 收集资料
    - label 分析内容
    - label 输出报告
  2. 02

    按名称找到模板配置

    模板注册表像一张“名称 → 配置”的对照表。下面是原库该模板的设计配置：

    design: {
  title: 'default',
  structure: { type: 'list-grid' },
  items: [{ type: 'compact-card' }]
}

    这一步确定：谁负责排列、谁负责画每一项。

  3. 03

    按组件名找到真正的程序

    getStructure('list-grid') 找到网格组件；getItem('compact-card') 找到卡片组件。解析器再合入用户参数与主题信息。

    list-grid → 网格排列程序compact-card → 卡片绘制程序
  4. 04

    把卡片程序交给网格程序

    运行时向结构组件传入 data、Title、Item、Items、options。网格通过 Item 调用卡片组件，因此可以复用同一套排列逻辑，换成另一种兼容的卡片。

    调用每个数据项时传入当前内容 datum、数据位置 indexes 和绘制坐标 x、y。统一的输入约定让组件能够组合。

  5. 05

    测量尺寸，计算每张卡片的位置

    网格组件先测量首个数据项的边界，再根据列数和间距计算各项位置。原库默认三列，间距为 24。

    行号 = floor(序号 / 列数)
列号 = 序号 % 列数
x = 列号 × (卡片宽度 + 间距)
y = 行号 × (卡片高度 + 间距)
    假设卡片宽 200、三列、间距 24：
    收集资料x = 0，y = 0分析内容x = 224，y = 0输出报告x = 448，y = 0

    第四项进入下一行。这里的宽度 200 是教学假设，实际尺寸由组件测量获得。

  6. 06

    生成 SVG，再显示和编辑

    组件返回 JSX 元素，由库的 JSX 渲染器生成 SVG。后续渲染处理文字、样式与资源并放入网页容器；开启编辑模式时，再创建编辑器。导出功能读取最终图形。

“可插拔”具体发生在哪里？

绘图扩展 / 注册与组合

登记名称 → 查找实现 → 按接口调用

结构、数据项、模板等有各自的注册表。新增能力时先加载代码，再注册；配置通过名称选择对应实现。

// 原库结构注册机制的核心
const STRUCTURE_REGISTRY = new Map();
registerStructure(name, implementation);
getStructure(name);

模板负责选择与组合。自定义组件负责实现新的绘图能力。

编辑器插件 / 生命周期

注册实例 → 初始化 → 使用 → 销毁

插件提供 name、init、destroy。管理器初始化插件时传入事件、编辑器、命令和状态等能力；注销时调用销毁方法再移除实例。

init：接入功能和事件destroy：清理资源和监听

工具栏或交互行为涉及这一层；卡片外观和排列方式主要涉及绘图组件层。

当前理解的边界
  • 写一个新名称不会自动加载新代码，扩展实现需要先导入并注册。
  • 替换组件需要满足接口和数据关系要求；不同结构与数据项的组合仍需验证。
  • v0.2.20 的标题解析仍调用默认 Title 组件，未提供与结构、数据项相同的标题注册路径。
  • 绘图注册表没有编辑器插件那样统一的卸载生命周期；注册同名项会覆盖 Map 中的映射，不等于已显示的图会自动更新。

后续探索与实现 / 全部待开展

用四个小实验，把解释变成可观察的过程。

下一次从第一个实验开始，每一步都展示输入、执行过程和输出，再进入下一步。

  1. 追踪一个模板

    显示原始输入、查到的模板配置、组件名称和最终 SVG。验收：能指出每一项内容在哪一步进入图中。

  2. 替换数据项组件

    保持数据和网格不变，制作并注册一张“开源项目能力卡”。验收：相同数据能切换两种卡片，并观察尺寸变化如何影响布局。

  3. 实现自己的排列规则

    复用同一张卡片，编写一个简单结构，再注册为新模板。验收：能展示每张卡片的坐标及计算依据，并检查长文字、空数据和多项内容。

  4. 实现一个编辑器插件

    开发一个简单的编辑器状态提示插件，观察初始化、事件处理与销毁。验收：启用后显示状态，移除后清理界面和监听，重复启停不出现重复响应。

最终要能亲手解释并实现：配置怎样找到程序、组件怎样组合、位置怎样计算，以及插件怎样接入和退出。

规划内容，选好模板，按规则成图。

通常直接复用内置模板；有特殊版式需求时再定制。模板与布局程序排列文字、形状和连线，输出 SVG，也可导出 PNG。

人或外部 AI 负责规划

Infographic 负责绘制

解析输入、计算布局、应用主题、提供编辑与导出。

03 / MECHANISM

实现原理

内容结构与视觉设计分开描述，最后由渲染引擎组合。

  1. 01描述内容

    语法或配置写入标题、数据项及其关系。

  2. 02选择设计

    模板指定布局结构、标题与数据项组件；主题控制配色和风格。

  3. 03布局渲染

    框架解析配置，组合 JSX 设计组件并输出 SVG。

  4. 04编辑与导出

    编辑器交互作用于画布，导出 API 生成 SVG 或 PNG。

“流式生成”是不断追加语法片段并重复渲染；本库不负责调用大模型。本页按钮只重播预设文本。
