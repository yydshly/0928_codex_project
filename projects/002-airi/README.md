## 六点摘要

### 1. 库的能力

把角色对话、语音、Live2D / VRM 表现、屏幕理解与外部工具组织在一起；提供 Minecraft、Factorio、Discord、Telegram 等专用集成。功能分布在主应用、独立服务和实验模块中，需分别配置。

### 2. 技术本质

面向虚拟陪伴的 Agent 应用工程。模型结合人设与上下文作出决策，按需接入感知和执行能力，再以声音、表情和动作呈现结果。陪伴是产品目标，操作是可扩展能力。

### 3. 可沉淀技术

模型与服务适配、语音输入输出流水线、角色动画与口型协调、工具调用与执行反馈、游戏状态读取与技能调度，以及多端共享模块的组织方式。实际复用仍需适配。

### 4. 使用场景

配置后的角色聊天与语音交流、桌面虚拟角色展示；接入视觉后的屏幕相关对话；运行专用服务后的游戏互动与社群聊天；多模态 Agent 原型验证。

### 5. 可扩展方向

桌面陪伴助手、游戏陪伴角色、角色化办公助手、虚拟主播与社群角色。需要按目标补齐长期记忆、主动交互、平台执行器、游戏接口或直播流程，并非全部现成产品。

### 6. 对我的意义

现阶段具有参考价值，保留为后期技术选型与实现参考，暂不继续深入研究或复现。待桌面女友出现明确的视觉、工具执行、游戏或角色表现需求时，再按模块查阅与验证。

## 关键结论

1. AIRI 的价值在于把多种模型与交互能力组织成角色应用。功能质量仍取决于模型、素材、服务配置与运行环境。
2. VRM 源码包含动画加载、自动眨眼、待机眼球运动、表情强度与过渡、口型及身体区域交互入口，不能概括为只有鼠标跟随。
3. 代码具备接口不代表交互自然。当前研究没有验证模型画质、语音延迟、动作衔接或持续陪伴质量。
4. 固定提交中的 Minecraft README 明确提示现有 Mineflayer 服务将逐步被 Fabric mod 方案替代；Factorio 的配置入口需要额外服务端集成。
5. 在线 0.11.3 手册仍把短期、长期记忆标为尚未提供。这只能说明文档状态；本次未证实新版本已经贯通完整的长期记忆流程。
6. AIRI 还包含独立的 `computer-use-mcp` 执行服务，当前主要面向 macOS，默认 dry-run 不注入键鼠；所研究的注册器没有 Windows 原生执行器。其参考价值在于工具调用、实际执行与状态反馈，不能将 Windows 客户端支持理解成 Windows 电脑控制已经就绪。
