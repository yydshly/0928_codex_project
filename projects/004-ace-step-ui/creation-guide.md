# ACE-Step UI：创作控制入口与产品参考

整体定位、模型支持与内部链路见 [完整理解说明](understanding.md) 和 [一张图总览](web/overview.html)。本篇聚焦具体操作和创作决策。

研究日期：2026-09-28。UI 固定提交：a1fdf91829ec6f7b98844f80e323529cd155dbf2。底层为独立部署的 ACE-Step 1.5；本机未运行模型，下面区分源码事实与创作/产品建议。

目标：理解如何让用户通过输入、参考、改编、局部修改与筛选，逐步接近可用音乐。网页入口：[创作控制指南](web/creation.html)。

## 六类核心入口

### 01 · 从一句话开始

- 用户素材：只有主题、场景或情绪，没有现成音频。
- 原版操作：创作面板 → Simple → 歌曲描述；可选语言、纯音乐，再生成。
- 控制范围：通过描述指定曲风、情绪、乐器和人声方向；模型补足未明确的音乐细节。
- 试听判断（分析建议）：方向是否对？有没有出现你想要的情绪、乐器和记忆点？
- 下一步（分析建议）：方向不对先改描述；有满意方向后，再进入自定义模式细化。
- 边界：自然语言属于引导；不是逐秒编曲指令，也不保证命中每个要求。
- 产品参考：把入口写成“我想做什么音乐”，提供场景提示和少量必填信息。
- [固定源码依据](https://github.com/fspecii/ace-step-ui/blob/a1fdf91829ec6f7b98844f80e323529cd155dbf2/components/CreatePanel.tsx#L1209)

### 02 · 从歌词或明确要求开始

- 用户素材：已有歌词，或已明确曲风、时长、节奏等要求。
- 原版操作：创作面板 → Custom → Lyrics / Style；设置人声或纯音乐，按需展开高级设置。
- 控制范围：歌词内容、风格描述，以及 BPM、调性、拍号、时长、语言等条件。人声性别选项以文字提示参与，不等同声音克隆。
- 试听判断（分析建议）：歌词是否清楚、漏唱或重复？句子是否唱得自然？主歌和副歌是否有区分？
- 下一步（分析建议）：文本问题先改歌词与分段；声音方向问题改风格。先改变一个主要因素，再比较结果。
- 边界：BPM 等是生成条件，准确程度待试听验证；旋律和歌唱细节仍由模型生成。
- 产品参考：把歌词编辑和音乐风格分开；高级推理参数折叠，不让新手一次填满。
- [固定源码依据](https://github.com/fspecii/ace-step-ui/blob/a1fdf91829ec6f7b98844f80e323529cd155dbf2/components/CreatePanel.tsx#L1550)

### 03 · 借另一段音乐的声音方向

- 用户素材：有一段想借鉴其音色、编制或氛围的音频。
- 原版操作：Custom → Audio → Reference → 上传或选已有音频；作品菜单也有 Use as reference。
- 控制范围：参考音频进入参考条件通路，结合你的文字描述影响音色与风格。
- 试听判断（分析建议）：你想借的特征是否出现？例如乐器质感、空间感、氛围；新作品是否仍符合自己的主题？
- 下一步（分析建议）：若只想借声音方向，继续调整参考与描述；若要保留现有音乐的结构线索，转向 Cover。
- 边界：不能把参考入口当作精确复制旋律、锁定歌手音色或完整克隆的承诺。
- 产品参考：上传后追问“想借鉴什么”，区分风格参考与改编原曲，避免同一个上传框承载不同预期。
- [固定源码依据](https://github.com/fspecii/ace-step-ui/blob/a1fdf91829ec6f7b98844f80e323529cd155dbf2/components/CreatePanel.tsx#L1371)

### 04 · 沿着已有音乐做改编

- 用户素材：已有源音频，希望在其基础上改变风格或声音。
- 原版操作：Custom → Audio → Cover → 选择源音频；或作品菜单 Cover song。高级设置可选 taskType 与 cover strength。
- 控制范围：源音频提供旋律、节奏等结构线索，新描述引导改编。强度影响源条件参与程度。
- 试听判断（分析建议）：想保留的音乐线索还在吗？新风格是否出现？人声与伴奏有无不自然变化？
- 下一步（分析建议）：保留太少与改编太少是两种问题，分别调整源条件强度和目标描述，和原版对照。
- 边界：不是一键只换乐器、其他全部不变。该 UI 将 audio2audio 映射到 cover，并非两种独立引擎。
- 产品参考：让用户先声明“保留什么、改变什么”；生成前显示预期，生成后能方便对照原版。
- [固定源码依据](https://github.com/fspecii/ace-step-ui/blob/a1fdf91829ec6f7b98844f80e323529cd155dbf2/components/CreatePanel.tsx#L2223)

### 05 · 保留大部分，只修改一段

- 用户素材：整体已满意，但某句、过门或片段需要修改。
- 原版操作：设置源音频 → 高级设置 → Task type 选 Repaint → 填开始/结束秒数及描述或指令。
- 控制范围：起止时间确定重新生成的范围；模型以源音频上下文约束局部修改。
- 试听判断（分析建议）：修改点是否改善？边界是否突兀？附近歌词、节奏、音色是否连续？
- 下一步（分析建议）：把编辑前、编辑段、编辑后连起来听；若只是裁掉静音或淡出，可直接使用音频编辑器。
- 边界：原版这里是起止数值输入；可拖动时间轴属于可改进设计。局部结果与过渡质量未在本机验证。
- 产品参考：让用户圈选区间、写明不满意之处、保留原版并随时撤回，避免每次修改丢掉好版本。
- [固定源码依据](https://github.com/fspecii/ace-step-ui/blob/a1fdf91829ec6f7b98844f80e323529cd155dbf2/components/CreatePanel.tsx#L2251)

### 06 · 从候选中挑选，再继续创作

- 用户素材：方向已确定，需要找到更合适的版本，或沿用成功的歌词和风格。
- 原版操作：高级设置中的 Batch size / Bulk generate / Seed；作品菜单中的 Reuse prompt、收藏与歌单。
- 控制范围：多候选用于探索随机结果；固定其他条件用于比较修改。Reuse prompt 回填歌词、风格、标题等部分字段。
- 试听判断（分析建议）：哪版更贴合用途？它好在哪里、差在哪里？记录可描述的理由，再决定下一轮改什么。
- 下一步（分析建议）：保留一个基准版本；全局不满意改生成条件，局部不满意转 Repaint，音频修整转编辑器。
- 边界：Reuse prompt 不等于恢复所有参数或保留原旋律。批量越多不保证越好；同一 seed 也不等于跨模型完全复现。
- 产品参考：支持基准版本、对照试听和修改理由。完整参数快照与父子版本关系是应补充的产品能力。
- [固定源码依据](https://github.com/fspecii/ace-step-ui/blob/a1fdf91829ec6f7b98844f80e323529cd155dbf2/components/CreatePanel.tsx#L490)


## 辅助与进阶入口

| 入口 | 原库能操作什么 | 做产品时应怎样理解 |
| --- | --- | --- |
| 格式辅助 | style / lyrics 调用格式服务，可能回填描述、歌词、BPM、时长、调性、拍号、语言 | 是输入助手；显示改动并允许确认，不承诺一键提升听感 |
| Enhance / Thinking | 触发不同的描述增强与规划条件 | 需要模型与 LM 支持，不能把开关数量等同于产品质量 |
| LoRA | 路径输入、加载/卸载、启用、强度控制 | 适合有兼容适配权重的用户；提供参考歌不等于完成训练 |
| Audio codes | 高级设置输入已有音乐 codes | ACE-Step 的进阶结构条件，不是通用云模型字段 |
| 参数 JSON | 导入部分已知生成字段 | 可以参考参数保存/恢复的方向；字段和运行环境仍需对齐 |
| 编辑 / 分轨 / 导出 | 作品菜单连接独立工具 | 用于后期加工与交付；不等于已有完整 DAW |

依据：[格式辅助](https://github.com/fspecii/ace-step-ui/blob/a1fdf91829ec6f7b98844f80e323529cd155dbf2/components/CreatePanel.tsx#L688)、[LoRA](https://github.com/fspecii/ace-step-ui/blob/a1fdf91829ec6f7b98844f80e323529cd155dbf2/components/CreatePanel.tsx#L1741)、[参数导入](https://github.com/fspecii/ace-step-ui/blob/a1fdf91829ec6f7b98844f80e323529cd155dbf2/components/CreatePanel.tsx#L446)、[作品菜单](https://github.com/fspecii/ace-step-ui/blob/a1fdf91829ec6f7b98844f80e323529cd155dbf2/components/SongDropdownMenu.tsx#L180)。

## 源码核对后的关键区别

1. Reference 和 Source 是两种音频输入。Reference 用于参考条件；Cover / Repaint 使用源音频完成不同编辑任务。
2. Task type 下拉只有 text2music、audio2audio、cover、repaint。不能把模型文档的其他任务全部列为 UI 已验证操作。
3. [buildGradioArgs](https://github.com/fspecii/ace-step-ui/blob/a1fdf91829ec6f7b98844f80e323529cd155dbf2/server/src/services/acestep.ts#L133) 将 audio2audio 转为 cover；这两个名称不能被统计成两个独立模型引擎。
4. Repaint 的原版入口是起止秒数输入。拖拽时间轴、问题批注、一键撤回是可以设计的扩展，当前研究页的 mask 交互也不是原库实际生成界面。
5. [Reuse effect](https://github.com/fspecii/ace-step-ui/blob/a1fdf91829ec6f7b98844f80e323529cd155dbf2/components/CreatePanel.tsx#L490) 回填歌词、风格、标题及按歌词判断的纯音乐标志，没有完整恢复全部推理参数。
6. [handleGenerate](https://github.com/fspecii/ace-step-ui/blob/a1fdf91829ec6f7b98844f80e323529cd155dbf2/components/CreatePanel.tsx#L968) 中 Bulk generate 循环发起任务，后续任务随机 seed；Batch size 是单次任务中的批量参数。它们都提供探索候选的机会，不能保证增加数量就改善质量。
7. 同处一张表单的字段不保证在各模式具有相同效果。切换模型、模式或供应商后要检查参数实际传递与支持语义，不能只看控件存在。

## 以素材为起点的创作路径（本仓库建议）

### 只有一个想法：先找到方向，再细化

1. 说明用途、情绪、风格与人声需求 → Simple 生成少量候选。
2. 先判断方向与音乐记忆点，选一个值得继续的版本。
3. 进入 Custom 调整内容；保留歌词、风格等基准，明确下一轮只想改善什么。

注意：还没找到方向时，不必反复调推理步数或堆很多相互冲突的风格词。

### 已经写好歌词：先让内容唱得成立

1. Custom 输入歌词、段落标签和风格，设置语言与目标时长。
2. 试听漏唱、重复、咬字和句子节奏，再判断段落变化与旋律。
3. 修改难唱的句子或结构；若整体满意只差一段，改用 Repaint 做针对性尝试。

注意：歌词重写与曲风修改最好分轮比较，否则难以判断改善来自哪里。

### 有一段参考音乐：先决定借声音，还是沿着原曲改

1. 只想借音色、编制或氛围 → Reference，加上自己的创作描述。
2. 想保留源音频的音乐结构线索 → Cover，写清目标风格与需要保留的部分。
3. 对照试听；若目标是精确克隆声音或逐音符编辑，应先确认模型是否真能做到。

注意：参考与改编的预期不同，产品应在上传时就帮助用户分清。

### 有一版基本满意：围绕具体问题继续修改

1. 先记录不满意的时间点和问题：歌词、编排、音色，还是剪辑问题。
2. 局部生成问题 → Repaint；全局方向问题 → Custom / Cover；裁剪、淡出 → 编辑器。
3. 对照原版与修改版，检查改善及新问题；满意后保存、导出，保留可回退版本。

注意：原库有若干操作入口；统一的版本树、问题标记与一键回退是本仓库提出的扩展设计。


## 如何定义“好音乐”

先按用途决定验收标准，再选择修改入口。这是创作方法建议，不是经本机音频实验验证的固定配方。

- 完整歌曲：旋律与记忆点、歌词准确度、歌唱自然度、段落变化、整体情绪与声音质量。
- 口播配乐：是否遮挡人声、密度和能量是否合适、时长与画面配合、结尾是否自然。
- 游戏/氛围音乐：氛围一致性、变化幅度、用途所需的衔接或循环质量；不能因提示词写“循环”便默认无缝。
- Cover：需要保留的音乐线索、期望改变的声音特征，两项分别判断。
- Repaint：局部是否改善，同时检查相邻片段、歌词与节奏衔接。

建议循环：定用途 → 生成少量候选 → 选基准 → 写具体问题 → 选针对性操作 → 对照听 → 达标交付。每轮尽量围绕一个主要问题改动；这有助归因，但生成仍含随机性，seed 也不保证跨模型或环境完全一致。

### 45 秒产品介绍配乐示例

目标是轻快、无歌词、给口播留空间、结尾自然收束。选择纯音乐，描述轻快电子与柔和钢琴、稳定节奏、克制编排，设置目标时长。先比较少量候选，听是否抢口播，再按问题处理：整体过密修改描述；局部抢耳尝试 Repaint；只需要结尾淡出使用编辑器。最终放回实际视频验收。

这是计划和判断过程，没有编造音频输出或成功指标；文字要求也不是精确时间轴控制。

## 产品设计可借鉴与待补齐

| 用户决策 | 可借鉴的已有入口 | 可补充的产品体验（未实施） |
| --- | --- | --- |
| 我从什么开始 | Simple / Custom / Reference / Cover | 按想法、歌词、参考歌、现成作品分流 |
| 我要保留或改变什么 | 风格、源音频、强度、重绘区间 | 用通俗目标描述控制，并明确约束边界 |
| 哪版更合适 | 播放器、候选作品、收藏、歌单 | 对照试听、基准版本、时间点问题记录 |
| 下一次怎么改 | Reuse prompt、Cover、Repaint、编辑器 | 从具体反馈推荐相关操作；完整参数快照、父子版本、回退 |
| 何时完成 | 文件播放与导出 | 按使用场景验收，展示等待/费用与累计尝试成本 |

建议验证：用户是否选对入口、能否给出具体修改理由、修改是否改善、到可用作品需要几次尝试与多少等待/费用。不要只用“生成成功”衡量创作产品。

## 换成 MiniMax 时如何参考

本次没有核验 MiniMax 当前模型/API 的具体能力，不能默认它支持同样的参考、Cover 或局部编辑。

- 供应商无关：意图收集、候选试听、反馈、归档、版本关系、交付与用量管理。
- 逐项映射：文本、歌词、参考音频、改编、局部编辑、时长与其他控制，核对实际接口及语义。
- ACE-Step 特有或强相关：audio codes、LoRA、DiT / LM 推理参数，不直接移植成 MiniMax 控件。
- 若目标模型不支持某入口，产品应说明可用替代流程；不能用普通重新生成冒充“保留原曲”“只改这一段”等效果。
