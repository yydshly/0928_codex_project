FROM MODEL CAPABILITIES TO CREATIVE CONTROL

手里有什么，想改什么，
决定下一步怎么创作。

研究这个库的价值，是看它如何把模型能力变成可操作的创作选择：从零探索、给出约束、借助参考、改编已有声音、修好局部，再筛选成作品。

底层：ACE-Step 1.5入口核对：UI a1fdf91产品建议：本仓库分析

这是一份操作与产品分析指南。入口按固定源码核对；创作路径是待验证的方法，不代表已经实测出“好音乐”的固定配方。

START WITH YOUR MATERIAL

先选你的创作起点

按钮切换的是研究建议，不会调用模型。原版功能与建议增加的产品体验分别标明。

先找到方向，再细化

  1. 说明用途、情绪、风格与人声需求 → Simple 生成少量候选。
  2. 先判断方向与音乐记忆点，选一个值得继续的版本。
  3. 进入 Custom 调整内容；保留歌词、风格等基准，明确下一轮只想改善什么。

还没找到方向时，不必反复调推理步数或堆很多相互冲突的风格词。

先让内容唱得成立

  1. Custom 输入歌词、段落标签和风格，设置语言与目标时长。
  2. 试听漏唱、重复、咬字和句子节奏，再判断段落变化与旋律。
  3. 修改难唱的句子或结构；若整体满意只差一段，改用 Repaint 做针对性尝试。

歌词重写与曲风修改最好分轮比较，否则难以判断改善来自哪里。

先决定借声音，还是沿着原曲改

  1. 只想借音色、编制或氛围 → Reference，加上自己的创作描述。
  2. 想保留源音频的音乐结构线索 → Cover，写清目标风格与需要保留的部分。
  3. 对照试听；若目标是精确克隆声音或逐音符编辑，应先确认模型是否真能做到。

参考与改编的预期不同，产品应在上传时就帮助用户分清。

围绕具体问题继续修改

  1. 先记录不满意的时间点和问题：歌词、编排、音色，还是剪辑问题。
  2. 局部生成问题 → Repaint；全局方向问题 → Custom / Cover；裁剪、淡出 → 编辑器。
  3. 对照原版与修改版，检查改善及新问题；满意后保存、导出，保留可回退版本。

原库有若干操作入口；统一的版本树、问题标记与一键回退是本仓库提出的扩展设计。

SIX PRACTICAL ENTRY POINTS

六类核心操作入口

三个问题贯穿每个入口：我提供什么约束？我期待改变什么？生成后如何判断？

01

Simple · 直接生成

从一句话开始

你手里有：只有主题、场景或情绪，没有现成音频。

原库怎么操作
创作面板 → Simple → 歌曲描述；可选语言、纯音乐，再生成。
实际控制什么
通过描述指定曲风、情绪、乐器和人声方向；模型补足未明确的音乐细节。
生成后听什么
方向是否对？有没有出现你想要的情绪、乐器和记忆点？
下一步
方向不对先改描述；有满意方向后，再进入自定义模式细化。

自然语言属于引导；不是逐秒编曲指令，也不保证命中每个要求。

做产品时借鉴什么

把入口写成“我想做什么音乐”，提供场景提示和少量必填信息。

02

Custom · 细化内容

从歌词或明确要求开始

你手里有：已有歌词，或已明确曲风、时长、节奏等要求。

原库怎么操作
创作面板 → Custom → Lyrics / Style；设置人声或纯音乐，按需展开高级设置。
实际控制什么
歌词内容、风格描述，以及 BPM、调性、拍号、时长、语言等条件。人声性别选项以文字提示参与，不等同声音克隆。
生成后听什么
歌词是否清楚、漏唱或重复？句子是否唱得自然？主歌和副歌是否有区分？
下一步
文本问题先改歌词与分段；声音方向问题改风格。先改变一个主要因素，再比较结果。

BPM 等是生成条件，准确程度待试听验证；旋律和歌唱细节仍由模型生成。

做产品时借鉴什么

把歌词编辑和音乐风格分开；高级推理参数折叠，不让新手一次填满。

核对原版入口源码 ↗
03

Reference · 参考引导

借另一段音乐的声音方向

你手里有：有一段想借鉴其音色、编制或氛围的音频。

原库怎么操作
Custom → Audio → Reference → 上传或选已有音频；作品菜单也有 Use as reference。
实际控制什么
参考音频进入参考条件通路，结合你的文字描述影响音色与风格。
生成后听什么
你想借的特征是否出现？例如乐器质感、空间感、氛围；新作品是否仍符合自己的主题？
下一步
若只想借声音方向，继续调整参考与描述；若要保留现有音乐的结构线索，转向 Cover。

不能把参考入口当作精确复制旋律、锁定歌手音色或完整克隆的承诺。

做产品时借鉴什么

上传后追问“想借鉴什么”，区分风格参考与改编原曲，避免同一个上传框承载不同预期。

核对原版入口源码 ↗
04

Cover · 保留结构线索

沿着已有音乐做改编

你手里有：已有源音频，希望在其基础上改变风格或声音。

原库怎么操作
Custom → Audio → Cover → 选择源音频；或作品菜单 Cover song。高级设置可选 taskType 与 cover strength。
实际控制什么
源音频提供旋律、节奏等结构线索，新描述引导改编。强度影响源条件参与程度。
生成后听什么
想保留的音乐线索还在吗？新风格是否出现？人声与伴奏有无不自然变化？
下一步
保留太少与改编太少是两种问题，分别调整源条件强度和目标描述，和原版对照。

不是一键只换乐器、其他全部不变。该 UI 将 audio2audio 映射到 cover，并非两种独立引擎。

做产品时借鉴什么

让用户先声明“保留什么、改变什么”；生成前显示预期，生成后能方便对照原版。

核对原版入口源码 ↗
05

Repaint · 局部重做

保留大部分，只修改一段

你手里有：整体已满意，但某句、过门或片段需要修改。

原库怎么操作
设置源音频 → 高级设置 → Task type 选 Repaint → 填开始/结束秒数及描述或指令。
实际控制什么
起止时间确定重新生成的范围；模型以源音频上下文约束局部修改。
生成后听什么
修改点是否改善？边界是否突兀？附近歌词、节奏、音色是否连续？
下一步
把编辑前、编辑段、编辑后连起来听；若只是裁掉静音或淡出，可直接使用音频编辑器。

原版这里是起止数值输入；可拖动时间轴属于可改进设计。局部结果与过渡质量未在本机验证。

做产品时借鉴什么

让用户圈选区间、写明不满意之处、保留原版并随时撤回，避免每次修改丢掉好版本。

核对原版入口源码 ↗
06

Batch / Reuse · 探索与收敛

从候选中挑选，再继续创作

你手里有：方向已确定，需要找到更合适的版本，或沿用成功的歌词和风格。

原库怎么操作
高级设置中的 Batch size / Bulk generate / Seed；作品菜单中的 Reuse prompt、收藏与歌单。
实际控制什么
多候选用于探索随机结果；固定其他条件用于比较修改。Reuse prompt 回填歌词、风格、标题等部分字段。
生成后听什么
哪版更贴合用途？它好在哪里、差在哪里？记录可描述的理由，再决定下一轮改什么。
下一步
保留一个基准版本；全局不满意改生成条件，局部不满意转 Repaint，音频修整转编辑器。

Reuse prompt 不等于恢复所有参数或保留原旋律。批量越多不保证越好；同一 seed 也不等于跨模型完全复现。

做产品时借鉴什么

支持基准版本、对照试听和修改理由。完整参数快照与父子版本关系是应补充的产品能力。

ASSISTANCE & ADVANCED CONTROL

其他入口，分别补充哪一环？

AI 整理输入

Style / Lyrics 格式辅助、AI Enhance 和 Thinking 用于描述增强、元数据与结构规划。格式辅助可能回填 BPM、时长等字段，需要核对是否仍符合原意。

产品参考：显示修改前后差异，让用户确认辅助结果；不要把“增强”表达为必然更好听。

handleFormat 与字段回填 ↗

LoRA 与音乐 codes

Custom 中有 LoRA 路径、加载/卸载、启用和强度控制；高级设置可输入预计算 audio codes。适合已有适配权重或中间表示的进阶流程。

边界：需要匹配模型和文件；上传一首参考歌不等于完成 LoRA 训练，也不等于自动克隆歌手。

LoRA 操作区 ↗

剪辑、分轨与导出

作品菜单提供音频编辑、分轨和下载入口。裁剪、淡入淡出与生成式局部重做是不同工具，应按具体问题选择。

产品参考：围绕“修好作品并交付”串接工具；分轨有入口，不等于已经具备完整多轨编曲工作站。

作品菜单 ↗

读完源码后，三个容易误判的地方

  • Reference ≠ Cover：参考声音方向与沿源音频改编，应提供不同的用户预期。
  • audio2audio 与 Cover：界面有两个选项，但该桥接版本把 audio2audio 映射到 cover，不能按两个独立生成引擎理解。
  • Reuse prompt ≠ 完整复现：该入口回填歌词、风格、标题等部分字段；不能推定同时恢复模型、全部参数、seed 或原旋律。

A CREATIVE LOOP WITH DECISIONS

怎样逐步接近一首好作品？

先把“好”变成与用途相关的判断。口播配乐、完整歌曲和游戏氛围音的目标不同。

01 / 定目标

写清要服务什么

用途、受众、情绪、时长、人声需求；再决定哪些特征必须保留，哪些允许变化。

02 / 探方向

少量候选，先听整体

例如先比较 2–3 个候选，判断气质和记忆点。数量是工作方法示例，不是最佳参数结论。

03 / 定问题

留下具体反馈

“副歌没变化”“这句漏唱”“结尾突然切断”比“再好听一点”更能指导下一步。

04 / 选操作

让修改有针对性

全局方向改条件，结构改编用 Cover，局部缺陷尝试 Repaint，剪辑问题交给编辑器。

05 / 对照交付

确认改善，也检查代价

保留基准版、检查新问题。达到用途要求后停止迭代，导出并记录创作来源。

试听时发现的问题下一步优先尝试再次检查
整体曲风、情绪不对缩小风格描述；明确核心乐器与人声需求；必要时加入 Reference方向是否更贴合用途，有没有互相冲突的要求
歌词难唱、漏唱或重复检查句子长度和段落；调整歌词；整体满意后再定位局部修改歌词准确度、咬字、断句与旋律自然度
想保留音乐线索但换声音提供源音频，使用 Cover 并对照不同约束设置保留程度与改编程度是否同时符合预期
某个片段不好，整体满意保留原版，选择 Repaint 区间并说明目标片段是否改善，前后接缝与上下文是否连续
开头静音太长、结尾要淡出使用音频编辑器裁剪、淡出时长、切点和衔接；这类问题不必重新生成整首

ONE CONCRETE EXAMPLE / 方法示例

为 45 秒产品介绍做背景音乐

  1. 目标：轻快、无歌词、给口播留空间，结尾自然收束。
  2. 输入：选择纯音乐；描述“轻快电子与柔和钢琴、节奏稳定、编排克制”，设置目标时长。
  3. 探索：试听少量候选，先判断是否抢口播、节奏是否贴合画面。
  4. 修改：整体太密先简化风格与编制描述；只有中间片段太抢耳，可尝试局部重做；只差结尾淡出就用编辑器。
  5. 验收：放回实际视频，检查口播可懂度、节奏、衔接与时长。最终判断来自实际使用场景。

这里没有附生成结果，也不把提示词描述当作精确时间轴控制。示例用于演示决策过程。

WHAT TO BORROW FOR YOUR PRODUCT

把模型控制，翻译成创作决策

下面是基于原库入口提出的产品设计建议，未声称原库已实现完整流程。

入口设计

按“手里有什么”分流

从想法、歌词、参考歌、已有作品开始；下一步只展示相关的控制，不把全部字段堆在同一表单。

控制表达

先问“保留与改变”

将风格参考、结构改编和局部修改解释清楚；展示模型能支持的范围，再按需展开专业参数。

反馈与版本

让每次修改有依据

支持时间点批注、基准版、对照试听、完整参数快照与版本关系。原库的复用、收藏和歌单可作为起点。

完成与成本

帮助用户走到可用结果

在生成前说明预计等待或费用，在生成后提供编辑和导出；用可用作品和完成率衡量价值。

如果换成 MiniMax，哪些思路仍然成立？

可独立借鉴：创作意图收集、候选试听、问题反馈、作品归档、版本关系与交付流程。

需要逐项映射接口：歌词、参考音频、Cover、局部重绘、时长及其他控制。原库有入口，不代表另一家模型支持同样语义。

强依赖模型：ACE-Step 的 audio codes、LoRA、DiT / LM 推理参数不能直接套用。这里未对 MiniMax 当前接口做能力核验。

建议验证的产品假设：用户能否选对入口？能否解释某版更好在哪里？修改后是否真的改善？从想法到可用作品需要多少次尝试、多少等待与费用？
