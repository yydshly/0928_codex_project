# 009 · Jev Ultrafast：快速网页智能体研究

[Jev Ultrafast](https://github.com/browser-use/jev-ultrafast) 由库读取可见 DOM、编号并维护节点映射，把目标、页面状态和候选选择题交给 TypeSafe Jev。Jev 返回操作与目标序号，库再映射到真实控件并执行；只有需要输入文字时，才调用另一个文本模型生成字段值。它通过缩短模型决策与浏览器读取路径，尝试让短流程网页任务更快完成。Jev 本身就是决策模型，其答案通常直接由程序执行，不需要每一步再交给另一个大模型。

## 五个问题看懂这个库

| 问题 | 摘要 |
| --- | --- |
| 能力是什么？ | 根据自然语言目标操作 Chrome 网页中的普通可见控件，完成点击、输入、选择、滚动和等待；没有提供桌面软件或手机 App 的执行器。 |
| 原理是什么？ | 本库读取 DOM、生成编号与合法动作；将目标、页面状态和选择题发给 Jev，接收操作与目标序号，再映射、复核并执行。只有 TYPE_TEXT 额外调用文本模型生成字段值。 |
| 价值是什么？ | 通过一次页面快照、合并操作与目标决策、按需生成文字来压缩网页任务的执行时间，并提供可拆解、可观察的浏览器智能体工程案例。速度改善有小样本证据，通用成功率和最低总成本仍未证明。 |
| 使用场景是什么？ | 上游检查过航班查询、指定百科文章导航和本地酒店筛选；可进一步研究内部网页后台、普通表单与筛选、网页流程检查、个人助手中的网页执行，扩展场景需接入与验证。 |
| 对我的意义是什么？ | 结合后端开发和 AI 工具使用经验，可把它作为网页自动化能力的研究起点，学习环境适配、受限动作选择、状态复核与独立验收；遇到真实重复网页任务时再评估接入，需求、交付效果和收益均需实践。 |

## 能力、效果与边界

支持从一个自然语言目标出发，在普通 HTML / ARIA 控件上选择 `CLICK`、`TYPE_TEXT`、`SELECT`、滚动、等待、完成或阻塞等动作。默认循环读取结构化页面状态而非截图，并在操作前检查目标是否仍有效。文本输入依赖单独的小模型和 API 密钥；决策依赖 TypeSafe Jev 服务与密钥。

作者公开的一次 Google Flights 搜索为 **7.073 秒**，目标是让单程、出发地、目的地、日期和匹配航班可见，未选购航班。三组交替配对测试里，新版中位耗时 **7.092 秒**，本项目旧版 **9.450 秒**，两组各通过 3/3。计时从初始页面观察后的首次预测开始，排除浏览器启动、初次导航及最终独立复核。该结果只覆盖同一任务、同一浏览器配置下的小样本，不能外推为通用可靠性结论。作者还给出 Wikipedia 与本地酒店页面的单次烟雾检查，分别为 2.798 秒和 1.896 秒；它们不是配对速度对照。

当前 DOM 读取未完整覆盖 Shadow DOM、iframe、Canvas、上传、新标签页、嵌套滚动及任意键盘组件。`DONE` 是模型选择，业务结果仍需独立验证。公开的约 **$0.00006272** 仅为演示中两次文本模型调用的费用，不包括 TypeSafe 和浏览器成本，无法据此认定总费用最低。

## 场景演示说明

研究网页提供三个**教学型步骤模拟**：航班搜索、打开指定百科文章、酒店搜索及筛选。它们根据作者披露的任务与结果归纳操作逻辑；页面按钮只切换本仓库编写的示意状态，不会启动 Jev、访问目标网站或产生新的测试结果。每个场景展示页面观察、动作与目标、输入文字来源以及独立验收点，帮助判断什么任务适合这一架构。

另有“请求与返回”交互：切换填写出发地、点击搜索、判断完成，观察候选问题、Jev 简化答案，以及是否会调用文本模型。页面还解释 node ID、eN 动作 ID、模型元素序号的关系，区分已测场景与后台操作、网页流程检查、个人助手等扩展设想，并列出运行前提和容易混淆的问题。

## 对我的意义与复用方向

对有后端开发基础、正在使用 AI 工具的你，本项目可以作为网页自动化和 Agent 执行层的技术参考。可沉淀“动态动作空间 + 一次请求决策 + 原子化页面快照 + 执行前复核”，以后结合具体的查询、筛选、表单或网页后台任务开发小工具；这是一条可探索的技术方向，尚无客户需求或收益验证。

若考虑用于自己的自动化流程，应先在目标网站上记录完成率、端到端时间、完整 API 费用和失败类型，再与直接 API 或固定脚本比较。这里的网页和插图是本仓库独立制作；上游代码、模型服务及 Browser Harness 各有自己的来源和使用条件。
