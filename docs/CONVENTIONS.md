# 项目维护说明

## 编号和公开索引

- 按收录先后分配 `001`、`002`、`003` 等编号；不重排、不复用。即使项目暂缓，也保留原编号并更新进度。
- 根目录 `README.md` 的索引表按编号升序排列。表格只放简短摘要，详细研究放在子项目目录。
- 每个条目在索引表下方对应一段图文摘要。建议包含项目名称、1～3 句研究摘要、一张有说明的图片，以及“原仓库 / 研究记录 / 演示”链接。尚未有图片或演示时，直接写明“暂无”。
- 链接应指向真实内容；不要提前填入尚未部署的演示地址。

图文摘要示例（有实际项目和图片后再填入）：

```md
### 001 · 项目名称

![图片内容的简要说明](projects/001-example/assets/cover.png)

简要说明研究对象、关注点和目前的发现。图片来源：自行截图 / 原项目（附来源与许可）。

[原仓库](https://github.com/owner/repo) · [研究记录](projects/001-example/research.md) · [演示](实际地址)
```

## 图片和第三方内容

- 图片放在对应子项目的 `assets/`，采用有意义的文件名，并写准确的替代文字。
- 自行制作的截图注明截图对象；引用原项目图片时，记录来源及许可。
- 不在此仓库批量复制第三方仓库。需要修改原项目代码时，记录版本、改动和许可要求。

## 多个网页演示

- 网页源码可放在各自的 `projects/NNN-name/web/`，依赖、构建和说明留在该目录。
- GitHub Pages 在同一仓库下提供一个站点；多个演示可使用不同子路径，例如 `/0928_codex_project/001-name/` 和 `/0928_codex_project/002-name/`。发布时按各项目的技术栈将构建产物汇集到对应路径。
- 单页应用若使用客户端路由，需要处理子路径和刷新回退；静态资源也应使用该项目的发布基路径。
- 演示真正上线并验证可访问后，再把链接加入根索引和子项目 README。
- 不同演示若需要不同部署权限或独立域名，可再拆成独立仓库，并在此处保留研究索引与外链。
